## G1 模拟图像与数字图像：本质区别与数字化环节

- 数字图像由像素（picture element）构成，每个像素都是其强度或灰度值的**有限、离散**数值表示，其取值来自以 x、y 为空间坐标的二维函数；该定义引自 Gonzalez 的《Digital Image Processing》（Pearson, 2018）[F001]。
- 栅格图像包含**固定的行数与列数**；像素是图像中最小的独立元素，保存着代表某一位置颜色亮度的**量化值**；这些值通常以压缩形式传输或存储 [F002]。
- 「数字图像」一词通常指**栅格（位图）图像**，与矢量图像相对 [F003]。
- Alvy Ray Smith 的技术备忘（Mesa Graphics 的《A Pixel Is Not a Little Square!》，Microsoft Technical Memo 6，1995-07-17）明确把问题定位为「正确地整合（converge）离散与连续」，并给出定义：**像素是一个点采样（point sample），只存在于一个点上；彩色图像中一个像素实际可能包含三个采样，分别对应在采样点处贡献于图像的三个基色** [F004]。
- PNG 规范（W3C Recommendation，2025-06-24）把 PNG 定义为用于**静态与动画栅格图像**的、无损（lossless）、可移植、良好压缩的可扩展文件格式，支持索引色、灰度、真彩色与可选 alpha 通道，**采样深度 1 至 16 位** [F005]。
- 图像编码国际标准 ITU-T T.81（1992）/ ISO/IEC 10918-1（1993）把编码过程分为**有损（lossy）与无损（lossless）两类**；其中「lossy」被定义为「非无损的编码与解码过程的描述性用语」 [F006]。
- T.81 的术语表把「**采样（sample）**」定义为「构成某一分量的二维数组中的一个元素」，把「**水平采样因子（horizontal sampling factor）**」定义为「某分量的水平数据单元数相对于其他分量水平数据单元数的相对数量」 [F007]。
- T.81 的术语表把「（均匀）**量化**」定义为「**通过线性缩放 DCT 系数以实现压缩的过程**」，并把「反量化（dequantization）」定义为其逆过程——解码器据此恢复 DCT 系数的表示 [F008]。
- **由此可支撑的「采样 → 量化 → 编码」三环节表述**：采样（离散化到点样本/样本数组）与量化（对系数做离散等级化）是两项彼此独立的、被同一国际标准分别定义的运算；编码（熵编码）则是把量化后的数据变成压缩数据流的过程。三者在 T.81 中并存且各自有定义 [F006][F007][F008]。

## G2 采样：定义、采样点与像素、采样精度（分辨率）及其单位

- **像素与采样点的关系**（本 gap 的关键区分点）：像素不是一个小方块，而是**点采样**；彩色情形下一个像素可含三个基色采样 [F004]。栅格图像的行/列数固定，像素保存量化后的颜色亮度值 [F002]。
- **分辨率单位**：W3C CSS Values and Units Level 4 的 `<resolution>` 类型定义三个单位标识符——`dpi`（Dots per inch，每英寸点数）、`dpcm`（Dots per centimeter，每厘米点数）、`dppx`（Dots per px unit）；`<resolution>` 单位的含义是「一个'点'在图形表示中的尺寸，即一个 CSS 英寸、厘米或 px 中能容纳多少个这样的点」；各 `<resolution>` 单位彼此兼容，`dppx` 为其规范单位 [F009]。
- **像素密度与分辨率的区分**：PPI（pixels per inch，每英寸像素数）描述的是图像在**物理表面或设备**上的细节密度，与「分辨率」不同——后者描述像素信息的总量而不管其缩放比例；像素本身没有固有的尺寸或单位（像素实际上是一个采样），只有当它被打印、显示或扫描时才同时具有物理尺寸与像素密度 [F010]。
- **像素数与物理尺寸的换算关系**：像素数 = 尺寸（英寸）× PPI [F010]。
- **采样精度对图像质量的影响**：若所选 PPI 低于设备能力，则画质低于设备所能呈现的水平——产生质量损失；若所选 PPI 过高，则像素被不必要地存储，造成磁盘空间浪费 [F010]。即分辨率过低会「马赛克/失真」，过高则「占空间」。
- **PPI 与 DPI 的区别**：现代喷墨打印机使用公制意义的 DPI（dots per inch）；二者与像素密度不同，因为**像素是任意颜色的单个采样，而喷墨打印只能打印某个特定颜色「有或无」的一个点**，打印机因此通过**抖动（dithering）**过程把像素转换为一系列点 [F011]。
- **位图内记录的分辨率**：Microsoft 的 `BITMAPINFOHEADER` 结构中，`biXPelsPerMeter` 与 `biYPelsPerMeter` 分别指定位图目标设备的**水平/垂直分辨率，单位为每米像素数** [F012]。

## G3 量化：定义、量化级数与位深、位深与可表示颜色数

- **量化定义**：在图像编码国际标准中，量化被定义为对变换系数做线性分级以换取压缩的操作，其逆过程为反量化 [F008]。结合栅格图像的定义（像素保存量化值）[F002]，可向学生说明「量化就是把连续的亮度/颜色值映射到有限个离散等级」。
- **位深与颜色数的权威对应（Microsoft GDI 文档）**：DIB 的 `bcBitCount` 成员「决定定义每个像素的位数以及位图中最大颜色数」——取值 **1**：位图为单色，调色板含 **2** 项，每个 bit 代表一个像素（0 取第一项颜色、1 取第二项颜色）；取值 **4**：最多 **16** 色，调色板最多 16 项，每像素用 4 位索引表示（例如首字节 0x1F 表示两个像素）；取值 **8**：最多 **256** 色，调色板最多 256 项，每字节代表一个像素；取值 **24**：最多 **2^24** 色，每像素为蓝、绿、红各 1 字节的三元组，调色板为空 [F013]。
- **位图与调色板索引的对应**：16 色调色板需要 4 位索引，因此把调色板颜色映射到像素颜色的数组同样由 4 位索引组成 [F014]。
- **索引色的上限（PNG 规范）**：PLTE 调色板块包含 **1 至 256** 个条目，每项为红、绿、蓝各 1 字节的三元组，条目数由块长度决定；该块必须出现在颜色类型 3（索引色），可出现在颜色类型 2 与 6 [F015]。
- **教学用换算关系（由上述来源可直接得出）**：1 位 → 2 色；4 位 → 16 色；8 位 → 256 色；24 位 → 2^24 = 16 777 216 色 [F013]。

## G4 编码：定义与作用，像素数据如何被编码压缩存储

- **PNG（无损压缩）**：只定义一种 PNG 压缩方法 0，它是带滑动窗口（距离上限 32768 字节）的 **deflate** 压缩；deflate 派生自 **LZ77**；PNG 内的 deflate 压缩数据流以 **zlib** 格式存储 [F016]。
- PNG 规范术语表同时标注：deflate 是 **LZ77 家族**的一种压缩方法（来源 RFC1951），zlib 是一种 **deflate 风格**的压缩方法（来源 RFC1950） [F017]。
- **GIF（LZW 压缩）**：GIF89a 规范规定，图像数据中「像素索引序列使用带可变长度码的 **LZW 算法**编码」；数据流首字节为 **LZW Minimum Code Size**，它决定图像数据中 LZW 码的**初始位数** [F018]。
- **JPEG（变换+量化+熵编码）**：T.81 的术语表区分了 **Huffman 编码器/解码器**与**算术编码器/解码器**；「字节填充（byte stuffing）」被定义为「由 Huffman 编码器或算术编码器在熵编码段中、在生成一个已编码的十六进制 X'FF' 字节之后插入一个零字节的过程」——说明熵编码段是 JPEG 压缩码流的组成部分 [F019]。
- T.81 中「块（block）」定义为「一个分量的 8×8 样本数组，或一个分量的 8×8 DCT 系数值数组」——这是 JPEG 编码「变换→量化→熵编码」链路的结构性依据 [F020]。

## G5 未压缩位图（BMP）存储空间估算的依据

- **文件头结构**：BMP 的文件头结构 `BITMAPFILEHEADER` 由 `WORD bfType`、`DWORD bfSize`、`WORD bfReserved1`、`WORD bfReserved2`、`DWORD bfOffBits` 五个字段构成（合计 14 字节）；`bfType` 必须是 `0x4d42`（ASCII 字符串 "BM"）；`bfSize` 是位图文件的字节数；`bfOffBits` 是从文件头起始处到**位图数据（bitmap bits）**的字节偏移 [F021]。
- **信息头字段**：`biWidth`、`biHeight` 给出图像宽高；`biBitCount` 指定**每像素位数（bpp）**，对未压缩格式该值即为平均每像素位数；`biSizeImage` 指定图像的字节大小，对未压缩 RGB 位图可置为 0；`biClrUsed` 指定调色板中实际使用的颜色索引数 [F022]。
- **像素打包方式（位深决定每字节装几个像素）**：1 位时每个 bit 代表一个像素；4 位时每个像素用 4 位索引，**一个字节代表两个像素**；8 位时**一个字节代表一个像素**；24 位时每个像素占红/绿/蓝各 1 字节共 3 字节 [F013]。
- **扫描线对齐（估算的偏差来源）**：Microsoft 对 DIB 的说明是——DIB 由「描述位图尺寸与颜色的结构」与「定义位图像素的字节数组」两部分组成；「数组中的位是紧凑排列的，但**每条扫描线必须用零填充至 LONG 边界**」（LONG 为 4 字节） [F023]。
- **BMP 也可压缩**：Windows 支持对以 **8 位或 4 位每像素**定义颜色的位图进行压缩；当位图信息头的压缩成员为 `BI_RLE8` 时使用**行程编码（RLE）**格式 [F024]。
- **由上述字段可直接推出课件上的估算式**：`未压缩像素数据大小 ≈ 像素量 × 位深 ÷ 8`；文件总大小还需加上文件头（14 字节）、信息头与调色板 [F021][F022][F013]；而由于每条扫描线要补齐到 4 字节，实际像素数据可能略大于该估算值 [F023]。

## G6 常见图像文件格式对比（BMP / GIF / JPEG / PNG）

- **PNG**：无损、可移植、良好压缩的栅格图像格式，是 GIF 的**无专利费替代品**（patent-free replacement），并可替代 TIFF 的许多常见用途；支持索引色、灰度、真彩色及可选 alpha；采样深度 1–16 位；**为网络等在线浏览应用设计**，可完全流式传输并支持渐进显示；提供完整文件完整性校验与常见传输错误检测 [F005][F025]。
- **GIF**：规范由 **CompuServe Incorporated** 发布（PNG 规范的参考文献将该规范记为 CompuServe Incorporated 于 **1990 年 7 月 31 日**发布的 *Graphics Interchange Format*）[F026][F027]。
- **GIF 的颜色与压缩机制**：全局/局部颜色表是「表示红-绿-蓝三元组的字节序列」，其字节数为 **3 × 2^(Size of Color Table+1)**；逻辑屏幕描述符中的 **Color Resolution** 为「原始图像每个基色可用位数**减 1**」，它表示原始图像整个调色板的大小而非实际用到的颜色数 [F027]；图像数据以 LZW 可变长度码编码 [F018]。
- **JPEG**：ITU-T T.81（1992）/ ISO/IEC 10918-1（1993）针对**连续色调**（continuous-tone）图像的压缩与编码；其解码过程「以压缩图像数据为输入，输出连续色调图像」；规范内定义了 8×8 的样本/DCT 系数块、量化表、有损与无损编码过程，以及 Huffman 与算术两种熵编码器 [F006][F019][F020]。
- **BMP**：Microsoft 的 GDI 文档把位图区分为「调色板索引式」（1/4/8 位，用调色板映射）与「直接式」（24 位，每像素 BGR 三元组），并说明其支持 4/8 位的 RLE 压缩 [F013][F024]。
- **工具侧的格式覆盖（可直接用于课堂演示）**：Windows 画图（Paint）可把作品另存为 **PNG、JPEG、BMP 和 GIF** 等多种格式，保存时由用户选择格式 [F028]。

## G7 位图（栅格）与矢量图

- **矢量图（SVG）**：SVG 2 规范定义「**SVG 是基于 XML 的语言，用于描述二维矢量图形以及矢量/栅格混合图形**」；SVG 内容可按不同显示分辨率缩放（scalable），可独立查看、可与 HTML 内容混排、也可用 XML 命名空间嵌入其他 XML 语言 [F029]。
- **位图侧**：数字图像通常即栅格/位图图像，与矢量图像相对 [F003]；栅格图像有固定的行列像素数，像素保存量化值，通常以压缩形式存储 [F002]；PNG 明确面向静态与动画**栅格**图像 [F005]。
- **教学用区分要点**：矢量格式记录的是「用数学/标记描述图形」，因此可无损缩放到任意显示分辨率 [F029]；位图格式记录的是「已采样并量化的像素数组」，放大即产生像素块 [F002][F003]。

## G9 课堂动手操作所依赖工具的官方依据

- **Windows 画图（Paint）**：绘画工具包括「铅笔、填充、**取色器（color picker）**、文字、**放大镜（magnifier）**」等，可完成裁剪、翻转、旋转、缩放等图像操作 [F036]；可通过「开始」选项卡的「调整大小」按**像素**或按百分比指定图像新尺寸 [F037]；可另存为 PNG、JPEG、BMP、GIF 等格式 [F028]。
- **Windows 照片查看器**：可使用「放大镜」按钮放大和缩小图片，并可在「**实际大小**」与「**按窗口大小显示**」两种视图之间切换 [F038]。
- **Windows 11「照片」应用**：可浏览、整理、编辑来自电脑、OneDrive 与 iCloud 的照片和视频，提供图库（Gallery）与编辑器 [F039]。
- **Python / Pillow 官方接口**：
  - `Image.mode`：字符串，指定图像使用的**像素格式**，典型取值为 `"1"`、`"L"`、`"RGB"`、`"CMYK"` [F040]。
  - `Image.size`：以**像素**为单位的图像大小，以 **(width, height)** 二元组给出；另有 `Image.width`、`Image.height` 给出单值 [F041]。
  - `Image.getpixel(xy)`：**返回给定位置的像素值**，参数 `xy` 为坐标 `(x, y)`；若为多图层图像则返回元组 [F042]。
